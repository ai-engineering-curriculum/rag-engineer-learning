## Overview

This track teaches the *engineering craft* of retrieval and RAG end-to-end for a hands-on specialist at level 30: document ingestion and semantic / structural / metadata-enriched chunking → embedding-model selection, MTEB / BEIR benchmarking, and domain-fit evaluation → vector-database internals across pgvector, Pinecone, Weaviate, Qdrant, Milvus, FAISS, Chroma with HNSW / IVF-PQ / ScaNN tuning → Lucene-family engines (Elasticsearch, OpenSearch, Solr, Vespa) with BM25, dense-vector fields, and classical learning-to-rank → hybrid retrieval with reciprocal-rank fusion, query rewriting (HyDE, decomposition, step-back), and semantic routing → reranking (cross-encoders, Cohere / Voyage / Jina rerankers, LTR rerankers, LLM-as-reranker) and context assembly with dedup, ordering, and per-chunk citation anchors → retrieval-specific prompt patterns for per-claim citation, refusal-when-no-context, and contradiction handling → retrieval-quality evaluation (recall@k, MRR, nDCG, precision@k, hit-rate) on TREC / BEIR-shaped judgment sets with paired significance testing → retrieval orchestration with LlamaIndex, LangChain, LangGraph, Semantic Kernel and the *exposure* of a tuned retriever as an MCP-compatible tool for downstream agents → retrieval MLOps (index versioning, retriever CI, ingestion DAGs, cost / latency optimization, corpus + query + quality drift monitoring) → enterprise-retrieval concerns (permission / ACL-aware retrieval, text-to-SQL over structured data, Graph RAG on property graphs, multimodal retrieval with CLIP / SigLIP / ColPali).

It is a **hands-on retrieval-engineering specialist track at level 30**, positioned in the **AI Engineering family**, between the LLM Application Developer (level 20, retrieval basics — hosted embedding APIs, pgvector top-k, grounded prompts) and the Agentic AI Engineer / Senior AI Infra Engineer (levels 40+, agent orchestration consuming retrievers and platform-scale retrieval infra). The differentiator against the peers `applied-ai-engineer-learning` (level 30, AI Engineering family — RAG *integration* at the product surface) and `ai-eval-engineer-learning` (level 30, AI Engineering family — application-layer RAG evaluation) is *retrieval-engineering ownership*: this curriculum builds and tunes the retriever + reranker + index; the peer tracks consume and product-surface a retriever with a fixed interface, and evaluate the *application* that wraps it.

Total planned commitment: **164 hours across 12 modules** + **120 hours across 3 projects** = **~284 hours**.

## Ownership rule

Following the project-wide ownership rule, this curriculum:

- **Owns** the engineering craft of retrieval end-to-end — document ingestion + chunking, embedding-model selection + benchmarking, vector-DB internals + ANN tuning, Lucene-family engines + LTR, hybrid retrieval + fusion + query rewriting, reranking + context assembly, retrieval-specific prompting (citation / refusal / contradiction), retrieval-*only* evaluation (recall@k, MRR, nDCG on judgment sets), retrieval orchestration + MCP-exposure of retrievers as tools, retrieval MLOps (index versioning, retriever CI, drift monitoring, cost / latency), and enterprise retrieval (ACL, text-to-SQL, graph, multimodal).
- **Defers down** to [`llm-application-developer-learning`](https://github.com/ai-engineering-curriculum/llm-application-developer-learning) (level 20) for retrieval basics (hosted embedding APIs, pgvector top-k, grounded prompts with citations, retrieval-vs-prompt triage) and for production Python service craft (FastAPI, asyncio) and general prompt engineering; to [`ml-engineer-learning`](https://github.com/ml-engineering-curriculum/ml-engineer-learning) (level 20) for classical ML fundamentals and the tf-idf / BM25 primer; to [`ai-infra-junior-engineer-learning`](https://github.com/ai-infra-curriculum/ai-infra-junior-engineer-learning) (level 10) for engineering-craft prerequisites (Linux, Git, Python, packaging, HTTP APIs, Docker).
- **Defers sideways** to [`applied-ai-engineer-learning`](https://github.com/ai-engineering-curriculum/applied-ai-engineer-learning) (peer, level 30, AI Engineering family) for RAG *integration* at the product surface (freshness / coverage / permission contracts consumed from a retriever, RAG-triad instrumentation at product layer, product-facing prompt shape); to [`ai-eval-engineer-learning`](https://github.com/ai-engineering-curriculum/ai-eval-engineer-learning) (peer, level 30, AI Engineering family) for application-layer RAG evaluation (RAGAS, TruLens, DeepEval, RAG triad — faithfulness / answer relevance / context precision-recall) and for general LLM / agent tracing (LangSmith, Langfuse, Arize, Phoenix); to [`ai-risk-engineer-learning`](https://github.com/ai-governance-curriculum/ai-risk-engineer-learning) (peer, level 25, Governance family) for content-safety and responsible-AI evaluation methodology (guardrail effectiveness, PII redaction methodology); to [`fine-tuning-engineer-learning`](https://github.com/ml-engineering-curriculum/fine-tuning-engineer-learning) (peer, level 30, ML Engineering family) for embedding SFT / LoRA / PEFT depth (sentence-transformers TSDAE, MultipleNegativesRankingLoss); to [`model-evaluation-engineer-learning`](https://github.com/ml-engineering-curriculum/model-evaluation-engineer-learning) (peer, level 30, ML Engineering family) for benchmark, statistical, and judge-vs-human calibration methodology depth; to [`ai-infra-mlops-learning`](https://github.com/ai-infra-curriculum/ai-infra-mlops-learning) (peer, level 25, Infra family) for general MLOps automation.
- **Defers up** to [`agentic-ai-engineer-learning`](https://github.com/ai-engineering-curriculum/agentic-ai-engineer-learning) (level 40) for agent orchestration and tool-use planning *consuming* the MCP-exposed retrievers this role builds; to [`ai-infra-senior-engineer-learning`](https://github.com/ai-infra-curriculum/ai-infra-senior-engineer-learning) (level 40) for retrieval-serving infra at platform scale (GPU-accelerated ANN, sharded cross-DC replication, HA plans); to [`staff-ml-engineer-learning`](https://github.com/ml-engineering-curriculum/staff-ml-engineer-learning) (level 50) for retrieval under web-scale streaming ingest (Kafka / Flink / Spark backing corpora); to [`ai-infra-principal-engineer-learning`](https://github.com/ai-infra-curriculum/ai-infra-principal-engineer-learning) (level 60) for cross-org retrieval-platform architecture.
- **Out of scope** to legal counsel (retention / data-residency legal opinion) and to the paired application track for user-facing product decisions on when to use retrieval at all.

## Module summaries

### mod-101 — Retrieval-Engineering Foundations and Role Position
Diagram the end-to-end RAG pipeline (ingest → chunk → embed → retrieve → rerank → assemble → generate) and name the engineering decision at each stage. Refresh classical IR (inverted indexes, tf-idf, BM25, precision / recall / F1) as the mental model every retrieval decision hangs off, drawing on Manning-Raghavan-Schütze *Introduction to Information Retrieval*. Read Lewis et al. 2020 and Gao et al. 2024 as canonical framing. Position the role on the ladder — what `llm-application-developer` (level 20) already owns and what `applied-ai-engineer` (peer, level 30), `ai-eval-engineer` (peer, level 30), `agentic-ai-engineer` (level 40), and `ai-infra-senior-engineer` (level 40) inherit or extend. Set up the local toolchain used by every downstream module.

### mod-102 — Document Ingestion and Corpus Preparation
Author an ingestion pipeline that handles PDF (native + scanned), HTML, Markdown, Office, and code — using unstructured.io, PyMuPDF, Docling, Nougat, and OCR fallbacks (Tesseract, AWS Textract, Azure Document Intelligence, GCP Document AI). Design semantic, structural (section-, table-, code-aware), and metadata-enriched chunking; go beyond naïve character windows to embedding-similarity segmenters, hierarchical parent-child chunks, and small-to-big retrieval. Attach retrieval-critical metadata (doc ID, section path, page number, publish date, author, permissions). Handle tables, formulas, and figures without losing the source cell reference needed for citation.

### mod-103 — Embeddings: Selection, Benchmarking, and Domain Fit
Distinguish bi-encoder, cross-encoder, ColBERT-style late-interaction, and SPLADE sparse-neural families. Read the MTEB leaderboard and the BEIR benchmark critically and run MTEB locally on a custom task. Compare hosted APIs (OpenAI text-embedding-3, Cohere Embed v3, Voyage voyage-3, Google text-embedding-005) vs. self-hosted open models (BGE, E5, Nomic, GTE, Snowflake Arctic Embed, Alibaba GTE-Qwen, Jina) on latency, cost, dimensionality, and quality-per-dollar. Design a domain-fit benchmark on your own corpus. Reason about quantization (int8, binary, Matryoshka MRL) and adaptive dimensionality. Defer embedding fine-tuning (SFT / LoRA / PEFT with sentence-transformers) to `fine-tuning-engineer` (peer, level 30).

### mod-104 — Vector Databases and ANN Index Engineering
Read the internals of the major vector DBs — pgvector (HNSW / IVFFlat on Postgres), Pinecone (serverless + pod), Weaviate, Qdrant, Milvus, FAISS (as a library with IndexIVFPQ / IndexHNSWFlat), Chroma — with managed-vs-self-hosted, hybrid-storage, filterable-attribute, and multi-tenant isolation trade-offs. Master ANN families (HNSW, IVF, IVF-PQ, ScaNN) and their recall / latency / memory frontier. Tune HNSW (M, efConstruction, efSearch) and IVF-PQ (nlist, nprobe, pq_m, pq_nbits) against a target recall@k and p95 latency using ann-benchmarks methodology. Design index sizing, shard / replica strategy, and metadata filter placement (pre-filter vs. post-filter correctness trap). Establish index versioning (deep-dived in mod-111). Defer platform-scale retrieval infra to `ai-infra-senior-engineer` (level 40).

### mod-105 — Lucene-Family Engines and Lexical / Learning-to-Rank Retrieval
Read the Lucene-family engine landscape (Elasticsearch, OpenSearch, Solr, Vespa) — managed-vs-self-hosted, licensing, ANN maturity, LTR plugin ecosystem. Author a production BM25 index (analyzer choice, field mappings, boosting, function scoring) as the strong lexical baseline every hybrid stack needs. Extend with dense-vector fields (Elasticsearch dense_vector, OpenSearch k-NN, Vespa tensor / HNSW). Implement classical LTR (LambdaMART, LambdaRank, RankNet via LightGBM ranking or XGBoost pairwise) with the Elasticsearch / OpenSearch LTR plugins. Reason about shard sizing (Elastic's 20-40GB heuristic), replica placement, and hot-warm-cold tiering. Defer web-scale sharding and cross-DC concerns to `staff-ml-engineer` (level 50) and `ai-infra-senior-engineer` (level 40).

### mod-106 — Hybrid Retrieval, Fusion, and Query Rewriting
Compose hybrid retrieval (BM25 + dense, and BM25 + dense + SPLADE) with reciprocal-rank fusion (Cormack et al. 2009) as the well-tested default; know when weighted-sum or Borda-count fusion fits better. Understand the score-scale mismatch that makes weighted-sum brittle. Implement query rewriting — HyDE (Gao et al. 2022), decomposition (multi-hop), step-back prompting, multi-query fanout — with the eval cost of each. Design semantic routing (intent classification, embedding-nearest-cluster, LLM router) with a reliability / latency budget. Handle filter-heavy queries. Defer product-surface retriever consumption to `applied-ai-engineer` (peer, level 30).

### mod-107 — Reranking and Context Assembly
Choose a reranker (cross-encoder like bge-reranker / ms-marco MiniLM, hosted like Cohere Rerank v3 / Voyage rerank-2 / Jina Reranker, LTR reranker with LightGBM / XGBoost, or LLM-as-reranker) with latency and cost trade-offs documented. Tune the retrieve-top-N → rerank-to-K funnel. Implement contextual compression (LlamaIndex ContextualCompressor, LangChain LLMChainExtractor) to shrink the reranked set to what fits the context window without losing citation anchors. Design context assembly (dedup by source, order by score or by document structure, per-chunk citation metadata, reserved token budget for the answer). Reason about long-context models (200K+, 1M+) — the 'lost-in-the-middle' effect (Liu et al. 2023) and cost-per-token still make a tight context the right shape.

### mod-108 — Retrieval-Specific Prompting
Author citation-instruction prompts that force per-claim source anchoring (inline bracketed citations, structured JSON citations, answer-with-quote) and validate them post-generation. Design refusal-when-no-context patterns (explicit "context does not contain the answer" training-shot, confidence-gated refusal) and the trade-off with helpfulness. Handle contradiction between retrieved chunks (surface disagreement, prefer most-recent / most-authoritative, hand off to a resolver). Detect and mitigate hallucinated citations (fabricated source IDs, wrong page numbers) with post-generation citation-verification checks. Baseline prompt engineering is owned by `llm-application-developer` (level 20); product-surface prompt shape by `applied-ai-engineer` (peer, level 30) — this module covers only the retrieval-specific slice.

### mod-109 — Retrieval-Quality Evaluation and Judgment Sets
Build a TREC / BEIR-shaped judgment set (query, relevant-doc-IDs) with curated or LLM-assisted labels + human spot-check. Compute recall@k, precision@k, MRR, MAP, nDCG@k, hit-rate with ir_measures / trec_eval / pytrec_eval. Do paired significance testing (paired t-test, Wilcoxon signed-rank, bootstrap CI on per-query score deltas) grounded in Sakai's *Metrics, Statistics, Tests* (2014). Design orthogonal ablation harnesses (chunker × embedding × retriever × reranker) and attribute which axis moved the number. Run BEIR / MTEB subsets and derive a corpus-specific delta. Application-layer RAG eval (RAGAS, TruLens, DeepEval, RAG triad — faithfulness / answer relevance / context precision-recall) is explicitly owned by `ai-eval-engineer` (peer, level 30, mod-105) — this module owns retrieval-*only* eval.

### mod-110 — Retrieval Orchestration and MCP Exposure
Compare LlamaIndex, LangChain, LangGraph, and Semantic Kernel for retrieval-orchestration use; know when to drop the framework and write the retriever bare. Use LlamaIndex advanced-RAG patterns (QueryEngine composition, SubQuestionQueryEngine, RouterQueryEngine, Property Graph Index) and LangGraph state-machine loops (retrieve + verify) as reference implementations. Wrap a tuned retriever as a Model Context Protocol (MCP) server (tool schema, streaming, resource-list vs. tool-call) using the official MCP Python SDK; wrap it as an OpenAI / Anthropic / Bedrock Converse tool endpoint for direct-consumer patterns. Agent orchestration *consuming* the MCP retriever is owned by `agentic-ai-engineer` (level 40).

### mod-111 — Retrieval MLOps
Establish an index-versioning convention keyed on (embedding-model, chunker-version, schema-version, corpus-snapshot); automate dual-index cutover with health checks and rollback. Build a retriever CI pipeline that runs the mod-109 judgment-set eval on every PR touching chunker / embedding / retriever / reranker code and gates on a recall@k / nDCG regression threshold. Set up index-build automation (incremental vs. full rebuild, backfill, ingestion-lag SLOs) with Airflow / Dagster / Prefect. Measure and optimize retrieval cost + latency (embedding-API cost per doc, vector-DB storage cost per M vectors, ANN-parameter-driven latency, cache tiers, quantization). Monitor for corpus / query / quality drift with alert thresholds. General MLOps automation is owned by `ai-infra-mlops` (peer, level 25); general LLM tracing (LangSmith, Langfuse, Arize, Phoenix) by `ai-eval-engineer` (peer, level 30).

### mod-112 — Enterprise Retrieval: ACL, Structured, Graph, Multimodal
Design permission-aware retrieval (filter at query time, filter at index time, per-tenant index isolation) with the SharePoint / Google Drive / Salesforce ACL-model shape enterprise corpora inherit; know the correctness traps. Implement text-to-SQL retrieval over structured data (schema-linking, few-shot SQL generation with LlamaIndex NLSQLTableQueryEngine or LangChain SQL agent, query-safety guards, execution-accuracy eval on Spider / BIRD). Implement Graph RAG on a property graph (Neo4j / Kùzu / Memgraph + LlamaIndex Property Graph Index or Microsoft GraphRAG) and know when graph structure lifts recall on multi-hop questions. Survey multimodal retrieval (CLIP / SigLIP for image-text, ColPali / DSE for document-page retrieval, audio embeddings, video-clip retrieval). Compose hybrid enterprise stacks (vector + lexical + SQL + graph behind a router). Content-safety / PII methodology deferred to `ai-risk-engineer` (peer, level 25); platform-scale cross-tenant isolation to `ai-infra-senior-engineer` (level 40).

## Assessment

Each module ships **1 quiz** plus the exercises and a lab listed in [`.aicg/curriculum-plan.json`](.aicg/curriculum-plan.json). Each project ships a portfolio-grade README, a reproducibility bundle (ingestion configs, index build manifests, embedding-model + reranker pins, retrieval-eval judgment sets with per-query relevance labels, retriever CI pipelines, drift-alert thresholds, MCP tool schemas, ACL test tenants), and an explicit rubric covering retrieval-pipeline completeness, chunker + embedding + index + reranker justification (with per-cell recall@k / MRR / nDCG evidence), retrieval-quality defensibility (paired-significance testing, ablation attribution), MLOps hygiene (index versioning, retriever CI, drift monitoring), citation-verification rate, permission-aware retrieval correctness under multi-tenant fuzz, and delegation-contract clarity with peer / higher-level tracks.

## Where to go after this curriculum

- **`agentic-ai-engineer-learning`** (level 40, AI Engineering family) — agent orchestration and tool-use planning that *consumes* the MCP retrievers this track builds; the natural next step for an IC who wants to move from retrieval to agents.
- **`ai-infra-senior-engineer-learning`** (level 40, Infra family) — retrieval infra at platform scale (GPU-accelerated ANN, sharded cross-DC replication, HA plans).
- **`staff-ml-engineer-learning`** (level 50, ML Engineering family) — retrieval under web-scale streaming ingest (Kafka / Flink / Spark).
- **`ai-infra-principal-engineer-learning`** (level 60, Infra family) — cross-org retrieval-platform architecture.
- **`applied-ai-engineer-learning`** (peer, level 30, AI Engineering family) — natural cross-training for the product-surface RAG integration peer.
- **`ai-eval-engineer-learning`** (peer, level 30, AI Engineering family) — natural cross-training for the application-layer RAG-triad evaluation peer.
